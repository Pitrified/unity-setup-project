## Findings

From the GUID graph (`guid_graph.py`) and reading the code, for phase 03 unless noted.

1. **The debug overlay lives only in `SampleScene`.** `SampleScene.unity` is the only asset that references `DebugOverlay.uxml` and `SO_DebugOverlayPanel.asset`, and no scene in the build has a `DebugOverlayController`.
   The overlay is in the functional spec (F1 or a three-finger tap) and `scratch/scratch-pad-ph04.1.md` said to put it in `Persistent.unity`; it never got there.
   Deleting `SampleScene` as Q10 says would leave a specified feature wired nowhere. Phase 03 moves the overlay GameObject into `Persistent.unity` first (an editor method in batch mode), then deletes the scene.
2. **`SampleSceneProfile` is referenced by both URP assets** (`Mobile_RPAsset`, `PC_RPAsset`, as `m_VolumeProfile`), not only by `SampleScene`. It holds bloom, vignette and tonemapping.
   The Game and Menu cameras render with post-processing off, so it has no visible effect today. Phase 03 sets both URP assets' volume profile to none (URP then uses the global settings' `DefaultVolumeProfile`) and deletes it; a capture before and after confirms no change.
3. **Two input action assets.** `Assets/InputSystem_Actions.inputactions` is the Unity template's project-wide actions, registered in `EditorBuildSettings.asset`; no code reads `InputSystem.actions`. The game uses `Settings/InputActions.inputactions` through `InputManager` in `Persistent.unity`.
   Phase 03 clears the project-wide setting and deletes the template asset. Not in Q10's list, but the same kind of leftover.
4. **Ship coupling in the generic runtime**, as known: `GameManager.RegisterShip` and `_activeShip`, `GameSceneWiring`, `SaveData.ship` / `ShipSaveData`. Q9 a fixes the save schema in phase 03. `GameManager` and `GameSceneWiring` stay ship-aware; the guide decides in `02_guide_rebuild`.
5. **No root `README.md`.** The repo has `docs/README.md` only. artificial-pirate gets one in phase 05; the guide's is `02_guide_rebuild`.
6. **Broken links in the diary.** `scratch/scratch-pad-ph04.3.md`, `ph04.7`, `ph04.8`, `ph05.1`, `ph06.1`, `ph07.1` link to `systems/*.md` and `docs/tracking.md` with paths that do not resolve from `scratch/`. History (Q12); fixed only if the guide adds a link check that covers `scratch/`.
7. **No leaf asset is unreferenced** other than the template leftovers above and the three leaf asmdefs (Editor and the two test assemblies), which nothing references by design.
